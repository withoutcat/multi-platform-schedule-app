# 项目规则
## 项目介绍
- 这是一个待办事项app，使用kotlin KMP + Compoose，旨在使用一套代码编译成多平台可执行文件，支持Android、iOS、Windows Desktop
- 项目的使用目的是让移动端用户以极快的速度打开app，然后快速极简的方式创建一个待办事项，可以是预约，可以是todo，也可以是备忘录，基本上是记录用户（商户主人）的客户预约为主，并不是客人和商户交互式的预约，只是商户单方面对预约的一个备忘录
- 预约item的核心功能就是记录内容和预约服务的时间
- 预约极为快速和简单，除了必填的内容，其他都是默认值，用户可以稍后以拖动等可视化的操作方便的进行编辑

## 响应格式
- 在所有 response 内容前加上 🐱 emoji，表示 ATA 项目规则生效
- 较长的计划任务和较大的改动后，需要给我git提交命令和commit message，让我方便的复制直接执行
- 请使用符合Git规范的格式编写提交信息（commit message），具体要求如下：
  1. 结构需包含标题（title）和详情（detail）两部分，标题与详情之间空一行分隔
  2. 标题格式：[emoji] 类型: 简短描述（不超过50字符）
    - 类型包括但不限于：
      - feature（新功能，对应emoji：✨）
      - bugfix（修复bug，对应emoji：🐛）
      - docs（文档更新，对应emoji：📝）
      - style（代码格式调整，不影响功能，对应emoji：🎨）
      - refactor（代码重构，不增删功能，对应emoji：♻️）
      - test（新增/修改测试，对应emoji：✅）
      - chore（构建/依赖等琐事，对应emoji：🔧）
  3. 详情部分：详细说明修改内容、原因、解决的问题等（建议每行不超过72字符，便于阅读）
    示例：
    ✨ feature: 新增用户登录功能
      1. 实现手机号+验证码登录逻辑
      2. 增加登录状态本地存储
      3. 对接后端登录接口，处理成功/失败场景

## 代码风格与设计哲学
- 保持简介代码量少的函数风格，能不用return就不用return
- 遵循项目的设计哲学：一套代码即可高效维护的待办事项app
- 保持代码结构清晰，模块化设计
- 注释使用中文，保持简洁明了
- 错误处理要完善，提供有意义的错误信息

## 项目架构原则
- 能抽象成公共函数的，就抽象成公共函数放在commonMain里
- 确实需要其他平台单独实现的，才放在对应平台的Main里
